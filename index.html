UIL / public overview
Product-level information

A bounded research workspace

Research with your browser, on your terms.

UIL coordinates a website workspace, an optional browser companion, and approved provider connections for user-authorized information workflows. It is designed to make visible results easier to review without turning the browser into an uncontrolled automation system.

Public information boundary

This page describes intended behavior and public capability status. It does not contain implementation specifications, private service details, credentials, internal APIs, or downloadable artifacts.

01 / What it does

A clear path from request to review

The product is organized around an explicit user action, a bounded operation, and a reviewable result. The user remains in control of the browser session and decides when a workflow starts or stops.

1. RequestDescribe or configure the research task.
2. ConnectUse an authorized browser session or approved provider.
3. ObserveRead bounded, visible results after the user starts the operation.
4. ReviewInspect a structured list or profile-oriented result.
5. DecideTake the next action manually or through an explicitly approved integration.

02 / High-level architecture

Three boundaries, one user-controlled workflow

Workspace

The website provides the primary interface for requests, result review, status, and capability messaging.

Browser companion

When browser-assisted mode is selected, an optional companion coordinates bounded operations in the user's existing browser session.

Approved providers

When an administrator configures an API or AI provider, the workspace can use that approved connection according to its declared policy.

Safety boundaries

Authentication, AI, write actions, and background activity are separate capability decisions rather than hidden defaults.

03 / Operating modes

Choose the boundary that fits the project

Browser-assisted mode

Uses the user's own browser session for visible, user-authorized research operations. A login or security interruption is handled by the user.

Available with user session

Full API mode

Uses an approved project API instead of the browser companion. An administrator must configure and authorize the provider first.

Administrator-configured

Sample mode

Demonstrates the interface with clearly labeled non-live data. Sample output must not be interpreted as evidence of a live connection.

Available

Default posture

Authentication and AI are off by default. Write actions and background crawling are disabled unless a future product explicitly authorizes them.

Conservative default

05 / Privacy and safety

Designed to stop rather than guess

User credentials stay with the user

The public product does not ask users to place passwords, browser cookies, or private session data into a website form.

Operations are explicit

Research operations begin from an intentional user action and are bounded rather than silently repeated or expanded.

Security challenges remain user decisions

If a connected service presents a login, checkpoint, CAPTCHA, rate limit, or security warning, the workflow stops for manual attention.

Capability status is visible

Unavailable, administrator-configured, and off-by-default capabilities are presented as such rather than simulated as complete.

06 / FAQ

Common questions

Does UIL collect my password?

No. Users authenticate with the connected service in their own browser or through an administrator-approved provider. The public product is not a password collection form.

Can it run without the browser companion?

Yes, when an administrator has configured an approved Full API mode. Otherwise browser-assisted mode uses the user's own authorized browser session.

Is AI automatically enabled?

No. AI is off by default and requires an explicit, approved configuration.

Does it crawl or act in the background?

No. The public operating model is bounded and user-initiated. Background crawling and unapproved write actions are not supported.

What happens when the connected service needs attention?

The operation stops and the user resolves the login, checkpoint, CAPTCHA, security, or rate-limit state manually before deciding whether to continue.

Where can an AI assistant read the public capability summary?

The repository publishes a small, sanitized capabilities.json file containing only product-level behavior and status.
